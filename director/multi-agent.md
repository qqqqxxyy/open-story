# 可选多 Agent 路线

如无特殊说明，不启用。只有明确要求或适用约定指定分工时使用；默认入口仍是[导演流程](workflow.md)。共同创作目标、裁量和来源边界按[共同契约](../role-interaction/director-author/contract.md)，作者执行[作者流程](../author/workflow.md)。

## 启用与准备

1. 宿主创建或续派当前分支的持续作者，冲突分支使用不同上下文。首次提供作者 ROLE.md、故事配置入口、node_id、导演包ID及必要调度信息；复用已经读过的规则和材料。
2. author-bind 只记录真实 session/agent 身份，不创建模型或作为作者读写门禁；无法恢复原作者时让新作者按实际上下文补读，不伪造旧身份。
3. 作者通过 director-handoff-read 展开包及真实来源一次，必要时在本幕范围补查。消息只传调度、回执索引或失败信息，不传正文、反馈、event 内容，不用临时文件交导演代提交。

## 普通幕交付

1. 导演完成并保存信息包后交作者创作；作者按普通幕流程完成文学作品和 review，用 author-reply-save 携 attempt_id 保存正文、按需反馈和实际导演包来源。
2. 作者保存成功才通知回执；导演按 packet_event_id 调 author-reply-read，核对作品来源与完整内容，不要求文学认可回合。优先呈现作品，不以通知中的摘要替代正文。
3. 导演用已完成作者包调用 scene-submit，组织完整 display 元信息并展示一次，当前稿等待反馈；导演只按返回任务维护已采纳前幕，先语义归档、再 Capsule。已成功阶段不重复提交。

## 同幕交互

1. 导演保存开幕或新增原始输入后，向同一作者提供 turn_id；作者按该 ID 定向读取增量，复用历史理解。
2. 作者用 dialogue-turn-save 保存片段并通知 fragment_event_id；导演用 dialogue-read 仅读取本轮后呈现。中间轮不同步阅读页，输入与完整回应不被归纳替代。
3. 自然结束或用户结束时，作者按交互流程完成整幕 review，再标完成或 dialogue-close 保存必要结尾，交整幕回执；导演用 author-reply-read 恢复未掌握的完整幕，再用 scene-submit(existing) 展示，按主流程等待反馈，仅维护已采纳前幕。

## 恢复

1. 先查 scene-status，确认原幕、绑定与已保存包；沿用成功的真实身份和来源 ID。
2. 正文或片段已存则按回执读取，不以新草稿替代；作者上下文丢失时按作者阅读准备恢复，已删后继与其他分支不带入新上下文。
3. 展示失败复用已存作者包及元信息恢复，归档失败沿同一 job_id 和批次重试，小修/大修及导演来源规则与单Agent一致。身份、作品、展示和归档分别确认；完成声明依实际回执。
