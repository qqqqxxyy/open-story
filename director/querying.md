# 创作资料查询与组织

先固定故事、分支、已采纳前驱截止点。scene-prepare 建立本幕上下文并返回默认 compact 召回；独立 scene-context 和 context-read 从该上下文读取，正常召回只选采用正文及其摘要，未采用的当前稿、旧稿和派生摘要不进入历史资料；小修或恢复只按作者包ID定向读取当前稿。迟归档前幕不回填本幕已固定的截止，前幕采用全文仍可直接承接。摘要和算法选集有损，遗漏不是人物不知道的证据。

## 接续已有故事的阅读准备

首次接续已有故事，或恢复后缺少此前的连续创作上下文时，主动阅读当前分支截止范围内最近至少 5 幕完整正文和 10 幕每幕摘要；已有幕数不足时读取已有部分，已经完整阅读的材料计入相应数量。

按叙事顺序理解作品当前的情节推进、悬念呈现、人物表现、关系变化、行文基调与承接方式，据此组织本幕资料与创作方向。对本幕涉及的人物、关系、历史经历或情节承接仍有具体缺口时，继续定向阅读相关正文与业务资料。

在 scene-prepare 固定本幕范围后、组织导演包前完成这项阅读准备。导演依据自己的上下文独立判断并补查，持续协作时复用已有理解；完成后沿用既有的信息包与创作流程。

### 接续阅读的 API 索引

先通过 history-list 查询本幕固定范围内最近幕摘要及真实来源指针，按不同历史 node_id 和叙事顺序选取所需的最近摘要与正文；已有完整阅读的上一幕计入阅读量。object 的 capsule 摘要另作长期背景参考。

批量阅读正文使用 context-read 的 prose 视图，传入按叙事顺序组织的历史节点。接口按配置的文本预算返回连续正文片段；按 page.next_cursor 续读到 page.complete 为 true，依序阅读同一正文版本的全部片段。片段保留原始字符与位置，页大小只影响传输。

参数、返回与调用示例按需查 context-read help；大文本的工具传输见[CLI读取指导](../script/cli/API.md#大文本读取与工具传输)。定位具体历史版本或段落使用 history-read；定向补查人物、关系与来源使用 context-read 的资料视图。

## 理解读者兴趣与本幕机会

按[读者期待方法](reader-expectations.md)结合本轮输入、多幕介入与自然语言讨论，区分明确要求、候选素材和兴趣推测，确定适用范围，保留依据和不确定性。方法在该专题维护，持续协作复用理解。

creative_intent 简明说明当前关注、期待体验、主要依据和范围；scene_need 据此提出值得发展的变化。召回寻找行动、关系变化、回响及信息差中的潜在矛盾，候选按[本幕情节可能性](planning-and-backstage.md#本幕情节可能性)构思，随导演包提供。

## 本幕资料召回与组织

scene-context 按 conf/creative.json 的数量、文本字段与 n-gram 策略召回人物、近期/相关远期记忆、事实、线索、痕迹、关系及已有设计。开启 capsule_mode 时还返回[长期背景摘要](capsule.md)与激活对象，摘要不占精确数量、不自动补原文尾部。默认 compact 返回当前业务投影和诊断，需同时核对原始来源时选 full：投影先按明确event ID执行替代和取消，再筛选；替代完整内容，不把多个源合并成一条旧event。重要远期记录可显式指定，疑点直接 context-read。content.status 等开放描述由角色结合经历理解；是否关闭、过时或仍值得使用由导演判断，当前采用视图通过显式 event_action 处理替代与取消。

导演组织顺序：

1. 本幕直接承接的动作、用户介入、人物与眼前处境。
2. 解释处境的有关经历、动机、关系余波和各人物所知。
3. 可能影响本幕的承诺、伏笔、线索、规划与真相。

只移除显著无关内容；不因为没有关键词就排除长期动机与承诺。把有关资料组成少量主题，说明联系、本幕意义和仍不确定之处。围绕同一事件组织时，区分后台真相、客观事实、猜测、口述、人物记忆与未来计划。

人物资料按[画像归档规范](archiving.md#人物画像增量侧写与长期归纳)组织，以已选人物的近期侧写 event、相关旧侧写与有效 capsule 一起理解当前人物。侧写和记忆分别按配置选取近期精确记录与文本相关的旧记录；关系从涉及已选人物的有效记录中，按叙事路径取全局最近的配置数量。需要补查的具体来源可显式指定或定向查询。

结合侧写中的适用情境、阶段性状态、时点与重要依据，说明人物持续特征、新侧面和变化；侧写的开放表意内容由导演与作者理解，跨幕摘要保留演变，API提供独立精确来源。实际经历、人物侧写和双方关系分别按各自职责组织，文学理解遵循[作者写作契约](../author/writing-contract.template.md#人物判断软约束)。

scene-context 的 selection_diagnostics 自动说明各类别候选、自动与显式选集、限额、选集首末来源、近期/相关数量及文本匹配统计，并同步到集中日志。排查遗漏时据此定位数量裁剪、人物筛选或文本排序，再决定是否补查；诊断不代替导演的资料取舍。

director-handoff-save 保存读者兴趣判断、本幕参考意见、情节可能性、这些组织说明与源 ID；缺失上下文或显式多 Agent 时 director-handoff-read 机械展开一次，去重，不二次召回或重新总结；默认连续主 Agent 复用已经组织的材料。原始输入及上一幕正文只呈现一次；来源追溯 ID 不递归展开。作者可用 context-read 定向查人物、object、类型、关键词、源 ID 或原节点正文。

复用已有上下文，不把已连续参与的作者当成每幕失忆的新作者。选集和信息包均为创作参考，作者按故事需要补查或重释。宿主工具未提供操作系统级隔离时，不将角色提示词宣称为硬权限隔离；创作 API 仍执行其明确的范围检查。

默认当前视图排除被替代/取消的目标与取消声明；source_event_ids仅指采用内容，操作目标不自动展开进作者材料。业务旧版本用context-read显式源ID或business-read的history；正文旧版明确评审用history-read的narrative_event_id或author-reply-read的packet_event_id；这些历史读不改变当前采用视图。


本幕召回正常使用scene-context默认compact，直接使用projection和capsules；需同时核对原始来源时选full。大结果可用CLI --output-file完整转储，Agent按当前缺口决定文件读取方式和范围。两种视图不改变选集、数量或范围，不因切换逻辑角色再次召回已掌握材料。


接续历史先用 history-list 取得最近幕摘要及真实来源指针；本幕补查传 scene-node-id，纯历史查询传 branch/cutoff，不开新幕。history-read 默认 prose，仅需段落引用选 paragraphs，需要完整诊断才选 full。多个同范围关键词合用 history-search 的 keywords，各词独立分页；完整多幕正文仍按 context-read prose 分页读取。持续单Agent复用已经完整读过的内容。
