# 导演提炼与归档

存储服务于作品。用户原文、导演组织结果与候选、作者完整回复及反馈、正文、记忆事实、规划秘密和创作记事入库。所有 event 都有唯一生产 node/object；来源、生效意图和表意细节留在开放 content。纯重试、错误和技术运行日志不写成创作 event。

正文只保存一个权威来源。普通幕为正文 event；交互幕各片段保存一次，正文 event 的 content 持有唯一的有序片段引用，作者包只引用正文 event，读取 API 展开完整文学正文。展示 JSON、HTML 与临时传输文件是派生物，不是第二个创作源。

## 导演的提炼顺序

当前完整稿先保存、展示并等待反馈；读者基于它开始独立下一幕或明确定稿后固定采用身份。下一幕展示后，依据 scene-maintenance 返回的采用稿与独立范围整理；不依据当前待反馈稿或后幕知识提炼：

1. 本幕确实发生、获知或改变了什么；只保存遗忘会破坏因果/知情连续性，或可能产生后续回报、反差、重释和余波的内容。
2. 公共事件与人物独有理解分开：公共详情保存一次，记忆保留人物的知情途径、主观理解和必要来源引用。
3. 保存实际关系变化、未兑现承诺和仍有效痕迹；普通装饰与瞬时情绪留在正文，获得后续意义时再记录。
4. 依据实际作品及必要作者反馈，沉淀采用的动机、背景与隐藏经历，调整受影响的规划、真相及记事；候选保留在导演包，正式资料以实际采用内容为依据。未来设计与已发生事实、后台知识与人物所知分别整理。无变化保留已有方向。
5. 通过 scene-maintenance 的 events 批量保存采用稿语义，再按返回任务处理 Capsule；API 追加到目标幕且不移动 head、不改变正文、不再次同步展示。scene-archive 保留旧流程兼容及底层组合用途，新稿不得绕过采纳任务直接归档。

## 人物记忆与画像

role_memory 保留人物经历、获知过程及当时的感受和理解；role_profile 保留人物新呈现的侧面、状态及描述变化；relationship 保留特定人物之间的互动发展、关系变化与重要约定。同一段经历可以贡献记忆、画像与关系资料，各自提炼其侧重点并保留来源联系。

### 人物记忆：按经历归并

每幕为参与本幕事件的各人物通常提炼 1—2 条人物记忆，以具有联系的经历、获知过程或认识变化为单位组织。这是提炼的软指导，数量随本幕实际内容自然伸缩。

一条记忆可以汇聚同一场交流、同一事件的连续过程，以及人物由此形成的理解。保留有叙事意义的具体细节、知情途径、因果联系和认识转折，使后续作者能够理解人物经历了什么，以及这段经历可能怎样影响其选择和关系。

公共事件的详情通过事实来源引用，人物记忆着重呈现其参与、所知、感受与理解。多个彼此独立且具有后续意义的经历可以分别成条；需要独立查证的获知点和认识转折保留清楚的来源与时机。跨幕演变通过[长期背景摘要](capsule.md)归纳，精确记忆保留各次经历。

### 人物画像：增量侧写与长期归纳

人物画像依据已发表作品与当前有效资料，整理人物截至当前叙事时点呈现出的身份、处境、声音、倾向、状态与相处方式，为后续文学创作提供简明参考。画像同时容纳长期特征与阶段性侧写，每项描述可以带有适用时段、情境、对象和来源。

按人物实际呈现的内容选取以下范围，用简明文字或少量条目组织：

| 内容类别 | 可记录内容与通用示例 |
| --- | --- |
| 身份、背景与生活处境 | 会影响当下选择的身份、背景和处境，例如最近开始承担照顾家人的责任、正在适应新的工作环境。 |
| 情绪与阶段性状态 | 近期情绪、精力、压力与关注点，例如这段时间情绪低落、最近对某件事格外敏感。 |
| 兴趣、偏好与生活习惯 | 喜恶、常去的地方、日常活动及其变化，例如不喜欢语文、偶尔回逛某家商店、最近开始喜欢夜间散步。 |
| 行为与应对倾向 | 面对压力、冲突、善意与困难时的反应方式，例如被追问时会先开玩笑、倾向自己尝试一遍再求助。 |
| 欲望、牵挂与边界 | 长期愿望、近期想做的事、在意之处及愿意接受的对待，例如最近想恢复一段联系、很在意别人是否认真听完自己的话。 |
| 声音与表达方式 | 语气、措辞、节奏、口癖及表达亲近或不满的方式，例如对熟人说话直接、表达关心时常从具体事务说起。 |
| 关系与相处习惯 | 面对不同人物的态度、互动方式及阶段性变化，例如最近对某位朋友有所疏远、与家人相处时更愿意主动解释。具体关系进展引用 relationship 来源。 |
| 自我认识与矛盾 | 人物怎样看待自己及言行中的复杂性，例如自认不在乎评价，却会反复想起别人的一句话。 |

已采纳幕归档时，结合采用正文、作者反馈和既有画像，整理相关人物新呈现的侧面、当前状态及已有描述的变化。新的喜好、情绪、习惯、处境、表达方式、相处态度或自我认识，都可以成为画像更新的内容。

稳定性格、口头禅及表达约定优先依据明确讨论或多次证据；一次有叙事意义的表现，可以形成一项带情境或时段的侧写，不自动升为永久人物规则。多幕中的重复、反差与发展，可以进一步丰富其描述。沿用同一人物 object，以本幕新呈现的侧面、阶段性状态或已有描述的变化追加 event，通常每幕每个人物归并为 1—2 条；保留适用情境、时段、重要依据与不确定性。初始侧写作为这一资料线的起点；跨幕的持续特征与演变通过[长期背景摘要](capsule.md)归纳，精确 event 保留各次呈现和变化。人物正常发展以增量侧写表达；同一时点的记录错误按下方显式事件规则更正。后续资料采用方式见[召回组织](querying.md)，作者对画像的理解与文学裁量见[写作契约](../author/writing-contract.template.md#人物判断软约束)。

## 业务结构与保存

最小必要业务结构由 schema_for_agent 的 content 定义和对应 CLI help 维护，其他表意字段开放。data 不解释这些字段；workflow 按类别得到业务视图。active 表示记录状态，不自动意味着当前采用；修订追加 event，事实替代、线索关闭和设计候选分别解释。

business-save 保存各类业务资料，business-read 读取当前采用内容及历史。已有 node 的维护由 API 编排 updating→追加→active；来源索引保存在 content，保存时校验读取范围。

## 显式事件操作

普通业务默认 append，向本幕记录实际发生的经历、获知和关系变化，保留发生时点与来源。同一 object 的历次进展累积为独立 event。

replace 用完整新内容更正旧记录的事实错误、记录错误，或同一时间与断言范围内不能同时采用的语义冲突。导演选择具体目标，在新 content 中说明旧问题和修订理由。cancel 用于撤销某条内容的采用；线索的自然完成和关系演变按发生过程追加。

replace/cancel 以新 event 改变当前采用视图，旧内容及归属保留。目标是同 object、当前路径可见且更早的 append/replace 记录；完整内容、目标参数与恢复方式按 CLI help。工作流先处理范围内的操作，再作相关性与数量筛选，历史和原始来源可定向查询。

未采用候选保存于导演组织/交接记录，正式 plan/truth/secret 保存选定内核及其必要修订。揭示、角色知情和生效条件由导演依据作品解释。长期背景摘要按[摘要流程](capsule.md)通过 capsule-save 保存，级别、来源及接替结构由 API 管理。


scene-maintenance 默认用目标采用正文作共同来源；条目显式 source_event_ids（包括[]）优先。兼容 scene-archive 可用 default_source_event_ids，只有未填写来源的条目继承。归档回执不再次展示。
