# 长期背景摘要

capsule_mode 开启时，精确召回与摘要概览是两条独立资料线。摘要按 object 整理，不按幕计数；调用时机见[导演流程](workflow.md)，格式按需查 capsule-check/read/save 的 CLI help。

从已固定的历史材料归纳人物声音、经历形成的动机、关系变化、承诺、未结因果和仍重要的具体细节。保留重要时间、获知时机与因果先后；摘要生产节点不代表其中经历的发生时间。保持事实、人物所知、推断与未来规划的边界；不要将十件事压成没有因果的泛泛评价。人物侧写与记忆、关系等沿各自 object 归纳；侧写摘要结合历次新侧面、阶段性变化及其情境，保留持续特征与演变依据。一级保留经历间联系，二级保留长期演变、转折和持续影响；目标篇幅是配置中的参考，不机械凑字。其他表意内容可放入开放content。

将 scene-context 返回的有效摘要与精确来源一起作语义筛选，导演包只保存摘要ID与必要的组织说明，并保留返回的激活对象索引。默认概览包含全部有效二级和未被其覆盖的有效一级；尚未归纳原文由精确召回处理，允许有损，不补整段原文尾部。

## 维护采用稿的摘要

1. 当前新幕展示成功后，沿 scene-maintenance 返回的已采纳前幕任务先完成语义归档；目标对象与独立读取范围由API确定。当前待反馈稿和废弃稿不作为摘要来源。
2. 若返回 capsule_pending，依据 capsule_jobs 的精确来源和批次归纳一级摘要，通过 scene-maintenance 提交 capsules；不手工构造批次、摘要控制元数据或另开 capsule-check。
3. 保存后直接使用 next_job 处理下一批、必要二级或下一待维护幕，直至 complete。Capsule关闭或未达阈值由API跳过；生成摘要不刷新阅读页，也不改变已开启后幕的读取截止。
4. 维护中断沿同一 job_id 与来源恢复，摘要归属目标已采纳幕，不把保存先后当作故事发生先后。

独立审计或明确维护仍可用 capsule-check/read/save：默认 jobs 仅返回有工作的对象，审计选 full；save 的 next_jobs 推进后续层级。它们不替代正常创作的 scene-maintenance 编排。

摘要有效性、接替与覆盖由 API 按当前范围计算，event.state 保留原存储状态。来源被更正或取消时，相关摘要及依赖它的二级摘要在视图中过时。重建沿用原批次剩余有效来源，追加同级摘要并声明接替关系；空来源批次按 API 保存接替记录。有效概览与精确资料分别读取，文学归纳由导演完成。
