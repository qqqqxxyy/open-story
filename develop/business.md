# 业务与角色提示词维护

工程改造沿用已确认的文学目标和角色权限；存储、接口或目录重构不授权重新发明故事性规则。文学材料开放、判断交给角色，技术保真与读取范围独立于文学裁量。

导演统筹短中长期方向、解释输入、组织资料、按需初始设计、展示和归档；作者阶段主要写本幕并通过 API 提交作品和反馈；默认同一 Agent 直接承接，显式多 Agent 才按回执读取，消息不承担作品传输。作者完整知情并可主动查询、重释与改写。信息包包括 scene_need 都是参考，不新增认可/审批回合。普通续写复用已有方向，明确新增/重构或无法承接才设计；根据实际作品仅维护受影响方向。

共同职责、交接态度、知情与来源边界在 role-interaction/director-author；两侧各写自己的应用，不复制整份契约。工作流写调用时机与创作判断，参数、默认、错误和返回由 help 暴露。

## 流程约束

- 开幕先创建节点并固定分支、前驱与读取范围；当幕资料有明确生产归属。
- 原始输入、来源和顺序如实保存，解释另存，不用正文或摘要反推原话。
- 普通幕由作者阶段完成作品和review，再保存展示并待反馈；独立下一幕轻量采纳前稿，展示新幕后再按维护任务归档前稿及Capsule；显式多 Agent 按实际回执读取；展示与发布/归档分别判断，最终回复后不承诺后台继续。
- 同幕交互复用开幕/归档，持续作者只接增量；轮次属于同一节点，保留完整片段与顺序，不逐轮重建整包或把对白归纳替代。
- 中断读取原幕状态并复用成功 ID/内容，不开新幕掩盖未完成流程。
- 候选、未采用方案、输入、作者反馈和记事按业务职责入库；纯技术运行日志与错误不写创作 event。

## 提示词有效性

角色目录只写现行行为、能力和真实限制，不写开发历史、测试样本或“本次改造”。能力变更后核对入口、流程、交互契约与限制；格式/链接通过不能证明文字语义正确。不删除有作用的文学规范来换取更短的文件。capsule_mode 以当前配置为准，开启后为独立背景线；精确召回不因摘要覆盖删除原记录或扩大为尾部全量回填。

## 维护与显式视图

一次删除>1个node，先返回具体范围和token，必须独立一轮普通聊天确认，再执行；token/CLI参数不是人类授权证明。目标之后删除保留锚点，重创包含目标并使用新ID，外部依赖阻止操作。删除/开新草稿同库事务，展示独立恢复；不把旧稿/已删秘密交给作者。

event_action 是唯一操作维度，允许 append/replace/cancel，summarize 为摘要，级别及版本接替保存在业务元信息中；普通业务归档只用前三种，摘要通过独立批量API。默认 append；replace/cancel 指定同 object、路径可见且先于本记录的 append/replace event，覆盖是完整替代而非 JSON 合并。取消控制记录不进入当前文学资料。后续 append 不恢复旧目标，恢复追加新记录。先归约完整范围，再限量召回；算法选集不代表全部历史。

未采用候选保存于导演组织/交接记录，不进入正式 truth/plan/secret 对象。条件、揭示和角色知情是开放内容，不由脚本机械推断。正常语义归档经采用稿维护任务写入目标幕，不改变后继范围；独立历史修订通过明确分支维护表达。

## 稿件与采用

scene_attempt标识初稿/小修/大修，scene_adoption固定采用正文、作者包、导演包与展示；scene_maintenance固定独立归档范围，scene_maintenance_complete表示完成。记录复用工作流object，原文只保存在user_input，稿件任务只存引用与输入指纹。node active与event active不等于语义维护完成。当前稿与旧稿禁止正常召回，允许按作者包ID定向恢复；旧active历史沿既有选择指针兼容，不补造历史adoption。
