# 数据开发约束

## 结构与责任

node 记录幕与基础结构；object 标识累积对象；event 保存原子内容；relation 保存归属与有向关系。字段与接口以 schema_for_data 为准，不在本文件复制整表定义。seq 第一，created_time 倒数第二，modified_time 最后；不预置无需求的保留字段。

event归属唯一保存于 relation_type=event：key 为 event，目标恰为一个 node 与一个 object。不在其他表冗余保存归属列表。正文、摘要、前驱是 node 固定指针，草稿可缺省，普通 scene 发布时完整；root 允许无这些指针。

data负责结构、合法JSON、唯一性、引用完整性、不可变字段、存储事务与高效查询，不解释人物知情、真相采用、增量/全量或故事条件。content 最小必要语义由业务契约定义，额外表意结构开放；生产节点用于检索，生效条件与内容来源留在 content，已登记的结构引用仍需依赖检查。创作来源索引仅保存在 content，不额外生成 creative_source 关系，也不扫描 JSON 来源索引实施删除保护。

## 不可变记录与生命周期

event.content/event_action/归属不可覆盖，修订追加；只允许契约明确的状态或指针修改。已发布节点维护由 workflow updating→追加→active。创建 event 与归属关系在同一事务完成；只在 creating/updating 写入业务内容。取消 event 受叶子节点条件约束，业务状态和采用版本不是同一含义。

节点通常不物理删除；明确叶子删除操作例外。叶子判断、依赖检查、清理与分支头处理在同一事务；外部保留引用阻止删除，不修改存活资料强行解除依赖。

## 分支与读取范围

所有叶子有唯一 branch_head，非叶子没有。普通续写沿原 branch；新 branch 只从已发布非叶子分叉，并创建新节点。head保存当前连接并更新，不逐节点补分支标记，不保存 cancelled 历史head。无head时branch object可保留。

创作读取先按当前分支前驱路径和固定截止范围筛选，再作业务召回；不读取全库后交给 agent 自觉过滤。关系/路径、来源与正文引用使用 JOIN/CTE/批量接口，不能在上层逐条查询。新增过滤评估索引与查询语句数量，优先使用已有组合能力，不要求无需求的压测。

SQLite是当前权威存储，正文源保存一次；展示JSON/HTML/索引是可重建派生物。文件适配暂占位，历史兼容转换在 script/compat 独立维护，正常业务不散布旧格式判断。源码仓库不跟踪 story-data。

反向前驱遍历通过descendants组合接口与node_predecessor索引，SQL仅在SQLite后端。范围删除通过一次归属/引用映射检查全部范围，内部引用不误判为外部；节点按叶到根清理，event/object归属规则不变。branch head最终按指定恢复分支统一处理，保留无head分支对象。

生命周期是workflow元数据event，节点/分支结构不新增列。共享历史节点信息默认共享，无分支专属历史修订。视图覆盖不删除旧event。目录扫描仅识别存储描述符，投影在pipeline，workflow/data不得反向依赖pipeline。

event_action是固定枚举字段，默认append；data只存储和校验字段，不解释替代、取消或摘要。工作流生成操作目标的结构关系，目标ID权威保存于content保留控制区域；关系用于引用完整性和删除依赖，不作为自动展开文学来源的指令。

摘要沿用summarize枚举和现有四表，不增加数据库列、来源relation或全局失效状态。摘要级别、来源与同级接替是业务JSON契约；有效、过时和被接替按分支与截止点计算。


## 统一发布与数据库兼容

数据库版本与兼容策略见[架构](architecture.md#统一发布与数据库兼容)。data 在业务解码前读取库级标记，并把真实写入和标记放在同一事务；连接配置只负责位置及身份，元信息通过数据接口暴露给高层。
