# 正常功能测试规范

测试假设按文档规范进行正常调用，验证功能符合预期；不要求单测、压测、攻击、恶意或极端场景，也不把迁移等价或全库一致性审计作为常规开发门槛。

## 增量补充

- 新增 API：补正常入参、返回契约、默认值、help与当前示例；按模块验证相应编排结果。
- 修改配置：用正常配置覆盖验证实际生效，不只检查文件存在。
- 修改数据/查询：验证归属、范围、引用和事务结果；重要批量查询检查SQL数量不随逐条引用增加，非压测。
- 修改日志：验证集中位置、已知目标、关联、耗时、结果/失败和轮转；日志不污染标准输出。
- 修改提示词：核对入口、链接、职责和能力描述，移除过期声明；不要为纯文学文案逐句写镜像测试。
- 修改示例：机器校验当前格式；需要执行的示例按所属正常功能场景验证，不默认为整套脚本。

## 执行与验收

tests/data/run.py 统一模块入口，开发默认运行修改功能对应的模块；全量功能测试与 E2E 在用户明确要求时执行。展示功能验收采用 API 回执、快照及 HTML 内容和状态的程序化检查。新增功能归入已有模块，确有独立业务域时才新增模块并注册，避免一脚本一测试目录。文档不写容易漂移的测试数量，数量以执行结果为准。

```powershell
& '<PYTHON>' -B -X utf8 tests/data/run.py --module runtime
& '<PYTHON>' -B -X utf8 tests/data/run.py --module all
```

测试通过只证明实际运行范围；分别报告功能、提示词结构和展示结果，不用格式检查证明文学效果，也不用短流程证明长期连续性。具体样本与本次开发脚手架不构成永久测试政策。

维护、管理、历史与显式记录处理分别注册模块；正常场景包括未确认零写入、范围变化重新确认、外部依赖阻断、重创原子初始化、生命周期恢复、批量段落搜索和旧包来源。具体脚手架与样本不写为永久规范。

摘要功能归入capsule模块：两级覆盖、批量阈值/预算、版本接替、分支与截止点、空来源接替、幂等保存、精确召回独立和真实CLI；场景隔离使用临时库。功能测试不代替长篇文学连续性评估。
