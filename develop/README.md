# 开发入口

本目录维护现行架构与增量开发规范，不是创作提示词。普通导演/作者不加载工程规范。本地历史方案、报告与迁移记录可保存在 docs（默认不纳入版本控制），具体 API 用法由 CLI help 生成，不在本目录复制参数表。

先读[架构](architecture.md)，按改动范围读[业务](business.md)、[脚本](script.md)、[数据](data.md)和[测试](testing.md)。历史故事迁移按[迁移规范](migration.md)执行，具体故事的调查与取舍报告放在 docs。各规范只有一份权威定义，其他目录只保留索引或本模块运行命令。

## 增量开发顺序

1. 定位用户需求、角色流程和代码层，核实现行入口，不把历史文档当规范。
2. 定位已有 schema/config/接口，复用权威定义；明确入参、结果、作用域、状态、重试与事务边界。
3. 在所属模块实现，注册同类操作，不扩张通用引擎或数据层责任。
4. 同步 help 元数据、示例、角色流程或交互契约，开放内容与必要结构分别处理。
5. 补对应正常功能场景，运行受影响模块；全量功能测试与 E2E 按用户明确授权执行，展示按测试规范做数据与产物检查。
6. 检查引用、依赖、示例及能力描述，报告改动、实际验证和未验证范围。保留既有改动，不自动提交或推送。

Python 使用项目指定 Conda 环境；不要因为 PATH 缺失而静默切换解释器。技术配置与数据格式跟随 skill_version，具体临时开发环境与样本不是永久架构政策。
